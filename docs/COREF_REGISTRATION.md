# Registration: coreference span discovery (semantic + graph walk with discourse edges)

Registered BEFORE any evaluation of the coreference substrate. Written while
the semantic/graph evaluation on the paraphrase and multihop variants
(docs/SEMGRAPH_REGISTRATION.md) is still running; nothing here depends on
those results.

## Research question

The manuscript conclusion leaves open whether coreference behaves like
paraphrase (one semantic hop suffices) or like multi-hop retrieval (a
chained walk is required). This track answers it with a substrate where the
answer sentence shares ZERO contentful tokens with the question by
construction.

## Substrate

`probes/probe_set_context_coref.yaml`, generated by
`probes/generate_context_probes_coref.py` (seed 11), committed before any
model evaluation.

- Needle pair: anchor "The {entity} office is run by a single site
  director." immediately followed by the answer sentence "Her personal
  passphrase, {word}, stays locked in the drawer."
- The question is the standard codeword question. The answer sentence
  shares no contentful token with it (not "security", "codeword",
  "office", or the entity). Only pronoun resolution to the adjacent anchor
  identifies it.
- 4 matched anchor+coref distractor pairs; depths 0.15/0.50; buckets
  256/3840; 16-prompt DEV arm at 1024 (calibration ONLY).
- Oracle span = the answer sentence (`needle_char_span`). The anchor span
  is recorded (`anchor_char_span`) for failure decomposition.

## Registered prediction (lexical baseline)

The single-stage IDF lexical detector finds at best the ANCHOR sentence
(entity token) and misses the answer sentence — 0% answer-span hit is the
registered expectation, mirroring the multihop single-stage negative.

## Detector: graph walk with discourse-adjacency edges

Same framework as SEMGRAPH_REGISTRATION.md (sentence nodes, lexical +
alpha * semantic edges, greedy budgeted walk from the question node,
latest tie-break, visited excluded, position 0 excluded, MiniLM frozen on
CPU) with ONE registered extension:

- Edge score for hop t -> sentence j:
  `lex(t, j) + alpha * cos(emb_t, emb_j) + gamma * adj(t, j)`
  where `adj(t, j) = 1` iff j immediately follows the sentence selected at
  the previous hop (0 for the first hop, which starts from the question).
- Rationale: pronominal coreference overwhelmingly resolves to the
  immediately preceding sentence; a discourse edge encodes that prior
  without any supervision or target-model forward pass.

Semantic-only detector (argmax cosine, no walk) is evaluated as the
paraphrase-style comparator.

## Calibration (dev only)

Grid: hops {1, 2, 3} x alpha {0.0, 0.5, 1.0} x gamma {0.0, 0.5, 1.0},
selected by answer-span hit rate on the 16 dev prompts only. Ties favor
larger hops, then larger alpha, then larger gamma. Evaluation-bucket
outcomes are never consulted during calibration.

## Frozen repair

Identical to SEMGRAPH_REGISTRATION.md: the same 16 identified OLMoE
retrieval heads, pre-softmax boost beta = 4.0, query region from the
question start, keys = detected span. Conditions: baseline (no boost),
oracle span, wrong span (width 16, random non-overlapping, seed 0),
semantic span, graph span.

## Endpoints and bar

- Primary: graph-vs-wrong paired answer-probability contrast on the
  3840-token coref bucket. Sign-flip permutation (2000 draws, seed 0),
  p < 0.05 AND |dz| >= 0.8.
- Secondary: semantic-vs-wrong (same bar) — this is the direct test of
  "coreference behaves like paraphrase".
- Descriptives: answer-span hit rate, anchor-only hit rate (detector found
  the anchor but not the answer), forced-choice accuracy, repair rate on
  baseline failures, fraction of oracle effect.

## Registered outcomes

- SUCCESS: primary bar cleared AND answer-span hit rate > 0.50.
- "Coref = paraphrase" verdict: semantic-only clears the bar at hit >= 0.90.
- "Coref = multi-hop" verdict: semantic-only fails but the graph walk
  (hops >= 2 or gamma > 0 selected on dev) succeeds.
- FAILURE: bar not cleared — reported as a registered negative.

## Scope

This track changes only the span locator. It does not alter the identified
head set, the boost, the main MoE results, or any prior registration. It
does not claim the transport mechanism is stronger; locator performance
and mechanism strength remain separate claims.
